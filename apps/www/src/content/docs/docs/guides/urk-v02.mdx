# URK v0.2

The v0.2 implementation is available in this checkout. Package manifests are `0.2.0`; publication is a separate step. Existing kernel methods, package names, adapter strings, legacy phases, and thin React/Next wrappers remain supported.

[Open the playground](/playground/). Pick the Explore, Create, or Connect object, or use the matching buttons. With the scene focused, keys **1–3** select and **arrow keys** rotate the selected object. Native buttons, the **Layout** select, and **Rotation** slider retain their normal keyboard behavior. Mouse and pen hover preview an object's callout without changing selection; the status surface announces selection. Narrow layouts place feedback below the canvas so it cannot cover selectable objects.

Touch interaction is tap-only. Touch contact and movement keep feedback on the selected object; a completed tap uses the browser's native click to select. Vertical swipes scroll normally without selecting or rotating objects. Leaving the scene, pausing, or losing graphics clears transient hover feedback and the pointer cursor. No drag gesture, pointer capture, or custom tap recognizer is added.

Selecting an object opens **Selection details** below the scene without moving keyboard focus. The native **Wireframe** checkbox changes that object's material; switching objects restores each object's current setting. Hover previews do not change the panel's selection. Close the disclosure, or press **Escape** inside it to close and return focus to its summary, without clearing selection. Details remain readable during pause or graphics loss, while the material control is disabled. Recovery preserves wireframe settings; a fresh kernel resets them and starts with details closed. This panel is application-owned DOM, not a new public overlay API.

The first v0.3 rendering/UI integration slice extends this same experience without renaming its v0.2 routes or exports. **Layout** transitions between Row and Arc using a finite application-owned animation, then returns to idle. Reduced motion applies the layout without animation. Enabling it during a running transition finishes on the next frame. Paused or graphics-unavailable scenes remain frozen and read the latest preference when animation can resume; a paused recovery redraw still leaves progress unchanged. Disabling reduced motion affects future transitions without replaying completed work. Preference changes alone do not schedule idle frames. Three remains an independent adapter; no rendering engine or UI framework is added. Loading reports actual initialization without an artificial delay.

**Enable sound** opts into the confirmation sound. Adjust **Volume** to save its level alongside your selection in browser storage under `urk:v02:preferences`. Invalid preferences are ignored. If storage is blocked, **Session only** indicates borrowed memory storage for the current page. Fresh kernels restore preferences but start silent. Pause disables interaction, freezes transition progress, and stops playback. Resize and theme changes can repaint that frozen view; resume continues any unfinished transition without restarting sound. Layout and rotation are local to the current kernel.

The host controls demonstrate pause/resume, optional diagnostics, unmount, deliberate setup failure, and fresh-kernel recovery. Activating a focused **Pause** or **Resume** button transfers focus to its newly enabled counterpart without scrolling. External lifecycle changes and actions on unfocused buttons do not claim focus, and application observers can redirect it elsewhere. When restart or setup-failure recovery replaces the controls, keyboard focus follows the matching replacement button only if an owned button still has focus. Focus moved outside the controls stays outside. Replacement cleanup preserves the responsive layout, while final teardown removes the owned controls and styling. A WebGL startup failure rolls back the owned surface; use **Start fresh** after restoring support. An unavailable sound file only affects the sound controls.

If the browser loses the WebGL context after startup, the scene shows **Graphics unavailable. Waiting for recovery.** Drawing and scene controls stop without resetting selection, rotation, or transition progress. When the browser restores the context, the same scene redraws automatically; unfinished transitions continue unless paused. Restoring a paused scene redraws its frozen view without resuming the kernel. Graphics loss does not change sound or runtime ownership. If the browser cannot restore graphics, **Start fresh** remains available; recovery does not run a forced retry loop.

## Simpler dependency access

```ts
import { createKernel, token } from '@urk/core';
import { createLoadingAdapter, LoadingCapability } from '@urk/adapters/loading';

const Preferences = token<{ volume: number }>('preferences');
const kernel = createKernel({
  frameMode: 'auto',
  serviceBindings: [{ token: Preferences, value: { volume: 0.5 } }],
  adapters: [createLoadingAdapter()],
});

await kernel.boot();
const ctx = kernel.getContext();
ctx.require(LoadingCapability).begin([{ id: 'content', label: 'Content' }]);
ctx.require(Preferences).volume = 0.8;
await kernel.shutdown();
```

Tokens infer the API type and identify one provider per kernel across adapters and borrowed services. Import the canonical token rather than recreating it by label. Services remain borrowed; cleanup drops references without destroying supplied values. Explicit string registry calls continue to work.

## Scheduling and startup

`frameMode: 'auto'` requests controller frames only after an update controller starts. An event-driven kernel can be running and idle. The default `continuous` mode preserves legacy behavior. Pause stops the kernel loop; external systems retain their own ownership.

Configured dependencies are checked before setup, including missing providers, collisions, and cycles. Forward references initialize before consumers. Setup is sequential by default; `adapterStartup: 'parallel'` starts independent dependency batches together. The playground declares its view dependencies before using this option. Dynamic registration needs already-published providers.

## Framework hosts and cleanup

React adds `useLifecycleSnapshot()` for operational state. Use provider ownership for a kernel the provider owns, and external ownership for shared host-owned kernels. Next defaults to provider ownership. Factories are inert; browser acquisition belongs in lifecycle hooks.

Built-in adapters register cleanup during acquisition so partial setup also releases owned resources. Shutdown signals cancellation immediately and waits for tracked work. A disposed kernel is terminal; create a new one to restart. Hooks must cooperate with cancellation.

Run `corepack yarn dev:v02` for standalone `/v02/` and React `/v02/react.html`, or use `/v02` in the Next proof. All hosts use the same private shared experience implementation.
